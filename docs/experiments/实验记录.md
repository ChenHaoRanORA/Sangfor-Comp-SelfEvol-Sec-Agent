## 2026-09-07：Agent v1 首次 llm-soc 178 全量研判评测（阶段三 DoD 验证）

### 背景与目标
- v1 Agent（LangGraph 处置流）能力边界：**仅告警 notify，无任何自主动作**。
- 规则引擎 v1 为"人工规则池"= 由 llm-soc 数据集 Wazuh `rule.id` 自动导入的规则种子；命中即 `fired_times++`，无衍生规则/自演化。
- 目标：跑通"规则命中 → LLM 研判 → 仅告警通知"闭环（对齐 [开发计划.md](../dev-plan/开发计划.md) 阶段三 DoD），并对照官方人工标注给出首轮准确率基线。

### 运行配置
| 项 | 值 |
|---|---|
| 运行日期 | 2026-09-07 |
| 环境 | conda `scssa`（python 3.10.21），langgraph 新版 API / openai 3.8 / pydantic v2 |
| 来源数据 | `data/processed/llm_soc_alerts.jsonl`（178 条，官方标注 TP=104 / FP=74） |
| LLM | `deepseek-chat` @ `https://api.deepseek.com`（key 来自环境变量 `DEEPSEEK_API`），temperature=0 |
| need_llm 策略 | `--llm-policy all`（命中即判，全部 178 条语义研判） |
| 命令 | `python scripts/run_agent_v1.py --source llm-soc --llm-policy all --out log/agent_v1_llm_soc_full_178.jsonl` |
| 产物 | `log/agent_v1_llm_soc_full_178.jsonl`（178 条 AlertEvent，仅 `action=notify`） |

### 运行结果
- 规则命中：178/178 全部命中（规则池共 74 条种子）；命中 TOP：rule 92032 ×28、92052 ×18、86601 ×10 …
- LLM：178 需研判 → 实判 176，**2 次 LLM 响应 JSON 非法自动回退规则结论**（`llm_error=true`，机制按设计工作，事件仍有 `action=notify`）。
- 动作集合：`['notify']`，未通知异常 0 —— 符合 v1"只告警、无自主动作"边界 ✅。

### 评测指标（vs 官方 TP/FP 标注，威胁检出为正例）
| 指标 | 值 |
|---|---|
| 混淆 | TP=70 / FP=8 / FN=34 / TN=66 |
| 准确率 Acc | 0.7640 |
| 检出精确率 Precision | 0.8974 |
| 检出召回率 Recall | 0.6731 |
| 检出 F1 | 0.7692 |
| 优先级一致率（LLM priority vs gt_priority） | 96/178 = 0.539 |

### 结论与短板定位
1. **精确率 89.7% / F1 76.9%，但召回偏低（67.3%）**：漏检 34 条官方 TP 集中在低危规则（level=3 漏 16、level=4 漏 6），以 Sysmon 低危行为为主 —— LLM 倾向判 FP。候选改进：提示词加入"低危但上下文成链"引导，或后续阶段引入"历史片段→可疑模式"记忆补充上下文。
2. **过度告警较少（8 条 FP）**，告警可信度尚可。
3. **2 次 JSON 解析失败**：模型输出多余字符/非法转义。候选改进：提示词明确"仅输出 JSON、勿用 markdown 代码块"；可在 [client.py](../../src/core/llm/client.py) 对 `extract_json_object` 增加容错。
4. **优先级一致率仅 53.9%**：判别（TP/FP）为当前主指标；LLM 按内容定级与官方按规则等级的定级口径不一致，后续评测优先级如需对比应统一判据或只看 TP/FP。

### 复现

## 2026-09-07：Agent v1 连通前端面板 —— 基于数据集事件流的大屏/告警/规则示例演示

### 目标与方案
- 把 v1 Agent 处置结果（离线事件日志）接进 Vue3 前端面板，做**基于数据集流数据的示例演示**。
- 数据流为**本地事件时间压缩回放**（零 LLM 成本）：后端按事件时间戳升序、按 `--eps` 每秒条数广播，前端大屏实时滚动展示。
- 面板范围：监控大屏 `/screen` + 告警列表/复核 + 规则页；审批 A3、NL 编译向导、自演化开关等未实现能力仍走本地 Mock。

### 交付产物
| 文件 | 职责 |
|---|---|
| `src/core/api/demo.py` | 数据层：Agent 事件 JSONL(处置结果) ⋈ 源告警 JSONL(原始细节) 按 seq 对齐，前端契约映射(severity/verdict/mitre/hitRules)、聚合(dashboard)、复核/规则编辑内存 overlay |
| `src/core/api/replay.py` | ReplayHub：观众驱动回放（无人在线空转、首个观众接入即从头播、可选 `--loop`），WS 广播 `kind=start/alert/done` |
| `src/core/api/server.py` | FastAPI：REST(dashboard/alerts/alert/review/rules CRUD) + WS `/ws/feed` + 静态托管 web/dist（同端口） |
| `web/src/api/*` | 前端数据门面接真实后端：dashboard/alerts/review/rules 走 axios REST，实时流走 `subscribeFeed` WS，断线指数重连 |
| `web/vite.config.ts` | dev 模式 `/api` `/ws` 代理到 127.0.0.1:8000 |

演示数据源（SOURCES）：
- `llm-soc`：`log/agent_v1_llm_soc_full_178.jsonl`（178 条 DeepSeek 实判）
- `linux`：`log/agent_v1_linux_full_offline.jsonl`（9,357 条规则回退，`llm_used=0`，可快放演示）

### 验证结果（后端 127.0.0.1:8000）
- `/api/health`：`ok=true`，`available=[llm-soc, linux]`，`dist=true`，replay 计数正确。
- `/api/dashboard`：todayTotal=178、Critical=11/High=60/Medium=10/Low=97、hosts=5、rulesActive=74（规则命中 178 次全部落库）。
- `/api/alerts?page=1&size=3`：total=178，verdict 均带真实 LLM `classification/priority/justification`。
- `/api/rules`：74 条数据集导入规则（含命中次数/24h 序列/审计）。
- WS `/ws/feed`：收到 `hello → start → alert…` 帧序列，alert 携带完整前端告警（观众驱动从头回放验证通过）。
- 静态 SPA：`/` `/screen` `/admin/alerts` 均 200。

### 复现 / 演示
```powershell
# 1) 启动后端（llm-soc 178 事件、~2 条/s 压到 ~90s 播完）
D:\Tools\Anaconda_envs\envs\scssa\python.exe -m src.core.api.server --source llm-soc --port 8000
#    或 linux 9,357 规则回退快放： --source linux --eps 60   ；展会循环： 追加 --loop
# 2) 浏览器打开（前端 dist 已由 npm run build 构建，与后端同端口托管）
#    监控大屏 http://127.0.0.1:8000/screen   （WS 实时事件流）
#    告警/规则后台 http://127.0.0.1:8000/admin/alerts  http://127.0.0.1:8000/admin/rules
# 3) 前端改造期调试：cd web && npm run dev（vite 代理 /api /ws 到 8000）
```
- 回放为“观众驱动”：无浏览器连接时空转；首个页面打开即从第 1 条事件完整回放，页面刷新会自动从头重播。
- 演示数据全部来自 Agent 真实运行产物；LLM 判定文本（`verdict.justification`）直接显示在告警详情，可对照本文件上一节的评测 TP/FP 样例讲解。
