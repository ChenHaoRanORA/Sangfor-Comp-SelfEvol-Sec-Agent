## 2. 开发环境与依赖

### 2.1 Python（conda 环境 `scssa`，Python 3.10）

```powershell
conda activate scssa
# 依赖核查（对应《开发指南》§2.1）
python -c "import langgraph, openai, fastapi, streamlit; print('core ok')"
python -c "import pandas, pydantic_settings, chromadb, kuzu, networkx; print('ok')"
```

Windows 下如不便激活环境，可用 `conda run` 直接执行（等价激活后运行）：

```powershell
conda run -n scssa python -m src.core.api.server --source llm-soc
conda run -n scssa python scripts/run_agent_v1.py --source llm-soc --limit 5
```

后端依赖（《系统架构》§7）：`langgraph`、`openai`、`fastapi/uvicorn`、`pandas`、`chromadb`、`kuzu`（0.11.3）、`pydantic` v2、`pydantic-settings`、`networkx`、`sqlalchemy`（或 sqlmodel）、`pytest`、`websockets`。实际代码大量使用标准库 `sqlite3`（未走 SQLAlchemy）。

### 2.2 前端（Node ≥ 18，仓库根 `web/`）

```powershell
node -v; npm -v
cd web
npm install     # 依赖见 web/package.json
npm run dev     # 开发服务器（vite，默认 http://localhost:5173）
npm run build   # vue-tsc -b && vite build → 产物 web/dist（含类型检查）
```

`web/package.json` 脚本：`dev=vite`、`build=vue-tsc -b && vite build`、`preview=vite preview`；Vite 开发服务器固定 `port: 5173`，`host: true`。

### 2.3 Windows 注意事项

1. **Kùzu 非 ASCII 路径**：Kùzu（Windows 构建）底层用窄字符打开路径，不支持中文路径。而本仓库路径含中文，故 `src/core/knowledge/graph.py` 与 `scripts/ingest_attack_kuzu.py` 在检测到非 ASCII 库路径时会自动回退到 `%TEMP%\scssa_kb\attack_kuzu`。生产建议设置环境变量 `SCSSA_KUZU_DB` 指向任意 ASCII 目录（如 `D:\Data\scssa\kb\attack_kuzu`），脚本与查询侧均优先读取该变量。
2. **conda run**：CI/脚本中避免逐条 `conda activate`，直接用 `conda run -n scssa python ...` 更稳定。
3. **耗时命令**：全量真实 LLM 跑批（llm-soc 178）约 178 次 DeepSeek 调用，注意限额与超时；调试/演示优先用 `--no-llm` 或复用历史产物。

## 4. 配置管理

实际实现为 `src/config/settings.py`：**普通 `@dataclass(frozen=True)`** + `os.getenv`，提供 `Settings.from_env()` 与带 `lru_cache` 的 `get_settings()`，并暴露属性 `llm_enabled`（= 是否配置了 API Key）。

> 差异提示：《开发指南》§2.2 规划用 `pydantic-settings` 加载 `.env`，但当前代码未使用 `BaseSettings`；`.env` 文件也不在仓库中（被 `.gitignore` 排除），配置完全来自进程环境变量。以下键名以代码为准。

| 环境变量 | 代码默认值 | 用途 | 读取位置 |
|---|---|---|---|
| `DEEPSEEK_API` | 空 | LLM API Key（空则 `LLMClient.available=False`，全链路回退规则结论） | `settings.py:31` |
| `DEEPSEEK_API_BASE` | `https://api.deepseek.com` | OpenAI 兼容端点 | `settings.py:32` |
| `DEEPSEEK_MODEL` | `deepseek-chat` | 模型名 | `settings.py:33` |
| `LLM_TIMEOUT` | `45` | 单次请求超时（秒） | `settings.py:34` |
| `LLM_MAX_RETRIES` | `1` | 重试次数 | `settings.py:35` |
| `SCSSA_KUZU_DB` | 无（回退 `%TEMP%\scssa_kb\attack_kuzu`） | Kùzu ASCII 库路径覆盖 | `knowledge/graph.py`、`ingest_attack_kuzu.py` |

`Settings` 另含三个固定相对路径（非环境变量）：`processed_dir="data/processed"`、`linux_alerts="data/processed/linux_apt_alerts.jsonl"`、`llm_soc_alerts="data/processed/llm_soc_alerts.jsonl"`。

安全约定：密钥只经环境变量注入，不入库、不写日志、不进代码；`.env`、`*.key` 已在 `.gitignore` 中；提交前自查。运行期日志不打印 Key，`LLMClient` 仅在异常信息里带异常类型与消息。

## 5. 核心模块开发说明

### 5.1 数据预处理与统一 Alert

- 脚本 `scripts/preprocess_datasets.py`：`python scripts/preprocess_datasets.py {all|linux-apt|llm-soc}`（位置参数，默认 `all`）。清洗两份数据集的分块表头/数组/时间格式，产出 `data/processed/linux_apt_alerts.jsonl`、`data/processed/llm_soc_alerts.jsonl`。
- 模型 `src/core/models.py`（Pydantic v2，`extra="ignore"`）：
  - `AlertRule`：`id/level/description/groups/firedtimes`（`id` 兼容 linux 的 int 与 llm-soc 的 str，引擎统一按 str 匹配）。
  - `Alert`：`dataset/alert_id/index/agent/os/time/time_raw/rule/mitre/decoder/location/program/text/priority/verdict/extra`；属性 `rule_id -> str|None` 与 `ts_ms`。`verdict` 字段存放数据集自带 ground truth（评测用，研判流程不读取）。
  - `RuleSeed`：人工规则种子（`rule_id/level/description/groups/mitre/sources/is_active/fired_times`）。
  - `RuleHit`：一次命中记录（含自增后的 `fired_times_after`）。
  - `Verdict`：`classification(TP/FP/UNKNOWN/None)/priority/confidence/method(llm|rule_fallback)/llm_error/justification/evidence`。
  - `AlertEvent`：单条处置事件（写 JSONL），含 `seq/ts_ms/ts_iso/dataset/alert_id/index/agent_name/rule_hits/need_llm/llm_used/verdict/action(默认 notify)/notified/channel`。

### 5.2 规则层与双规则池

- `src/core/rules/engine.py`：
  - `import_seed_rules(alerts) -> dict[str, RuleSeed]`：从告警流按 `rule_id` 聚合"人工规则"种子，保留首个非空描述/等级，合并 groups。v1 中"人工规则池"即由数据集 Wazuh rule 导入的种子。
  - `RuleEngine(seeds).match(alert) -> list[RuleHit]`：命中即 `seed.fired_times += 1`，返回单条 `RuleHit`（含 `fired_times_after`）。注意 **该 `fired_times` 是进程内内存计数，不落库**。
  - `stats()` 按生效次数倒序返回规则统计；`__len__` 返回种子数。
- `src/core/rules/pools.py`：记忆库侧的**人工权威规则池**（v3 分流用）。
  - `rule_covers(rule, rule_id) -> bool`：遍历 `rule["expression"]`，仅处理 `field=="rule.id"`，支持 `op in`（值集合成员）与 `op in {eq,==}`（字符串相等）。
  - `load_manual_rules(store, dataset=None) -> list[dict]`：取 `state=active` + `enabled` + `auto=0` + 携带非空 `expression` 的规则；`dataset` 过滤经其来源模式归属（无来源模式视为跨数据集全匹配）。
  - `match_manual(alert, manual_rules) -> list[dict]`：返回覆盖该告警 `rule_id` 的规则列表。
- 衍生规则的 `fired_times` 存于记忆库 `rule` 表，`MemoryStore.bump_fired/set_fired` 维护；v3 `memory` 通道命中过去模式时递增对应衍生规则计数（见 5.4）。

### 5.3 LLM 访问层

`src/core/llm/client.py`：

- `LLMClient(settings=None)`：内部按 `settings.llm_api_key` 惰性构造 `OpenAI(api_key, base_url, timeout, max_retries)`；`available` 属性表示是否已配置。
- `_chat_json(system, user) -> dict`：单轮 `chat.completions.create(model=..., messages=[system,user], temperature=0.0)`，经 `extract_json_object` 解析；异常统一抛 `LLMError`；成功时回填 `obj["_llm_meta"] = {"model", "cost_s"}`。
- `complete(system, user) -> dict`：通用 JSON 任务出口（模式归纳/规则编译/解释等）。
- `triage(dataset, text, rule_desc, rule_level, mitre, fingerprint, evidence=None) -> dict`：研判入口。用户消息按 `[数据集]/[命中规则]/[MITRE]/（可选 evidence）/ [告警内容]` 组装，告警文本截断 4000 字。
- 提示词 `SYSTEM_TRIAGE` 要求的输出字段为 `classification ∈ {TP,FP,UNKNOWN}`、`priority ∈ {low,medium,high,critical}`、`justification`。消费侧 `make_triage_resolver` 亦只读取这三项。**《开发指南》提到的 `evidence_ids`、`suggested_actions` 目前在提示词与解析中均未实现，以代码为准。**
- JSON 健壮性 `extract_json_object(text)`：先截取首尾花括号间内容严格 `json.loads`；失败则将"紧跟非转义保留字符的反斜杠"补成双反斜杠并 `strict=False` 重试，用以容忍模型在理由中直接写 `C:\Windows` 之类未转义反斜杠；仍失败抛 `LLMError`。
- 失败回退：处置流捕获 `LLMError` → `fallback_verdict(alert, hits)` 并置 `llm_error=True`、`method="rule_fallback"`。

### 5.4 处置流 LangGraph

`src/core/workflow/disposition.py`。

`AgentState(TypedDict, total=False)` 显式声明：`seq / alert / rule_hits / manual_hits / need_llm / channel / cover_patterns / evidence / evidence_counts / verdict / event`。

> **重要坑**：LangGraph 用 `TypedDict` 建通道，节点未在 `AgentState` 中声明的键会被静默丢弃（v3 的 `manual_hits/channel/cover_patterns` 曾因此无法在节点间流通）。新增跨节点状态时必须同步补充声明。

- **v1/v2**：`make_v1_graph(engine, need_llm, triage_resolver)` 等价 `make_v2_graph(..., evidence_builder=None)`。
  `make_v2_graph(engine, need_llm, triage_resolver, evidence_builder=None, use_memory=True, use_kb=True)`：
  - 节点：`match_rules`（`engine.match` + `need_llm(alert,hits)`）→ 条件边 `_route`：`need_llm=False` → `alert_only`；否则 `evidence_builder` 存在走 `gather_evidence` → `resolve`，不存在直接 `resolve` → `alert_only`。
  - `gather_evidence` 组 query=`text + 首个命中规则描述`（截 3000 字），调 `EvidenceBuilder.collect(..., seq_now=s["seq"])`，返回 `evidence/evidence_counts`。
  - `resolve` 调 `triage_resolver(alert, rule_hits, evidence)`；`alert_only` 组装 `AlertEvent(action="notify")`。
- **v3**：`make_v3_graph(engine, triage_resolver, evidence_builder=None, store=None, fallback_need_llm=None, manual_direct=True, conflict_feedback=False, conflict_by="system", bump_fired=True)`，按**命中源裁决**分流（事件带 `channel`）：
  1. `manual`：`match_rules` 同时算 `manual_hits=match_manual(...)`；`_route_manual` 在 `manual_direct` 且命中时走 `decide_direct`（`_manual_fallback_verdict` 按人工规则 severity 直接定级，**不检索证据、不唤醒 LLM**）。
  2. `memory`：否则进 `gather_evidence`；若命中"过去已成型的可疑模式"（`active_patterns_covering_rule`，防泄漏）或有相似记忆片段（`counts["frags"]>0`）→ `need_llm=True`；`bump_fired` 时对覆盖模式对应的 active+enabled+auto 衍生规则 `bump_fired`。
  3. `policy`：无记忆命中时按 `fallback_need_llm` 策略决定是否 LLM（无证据）。
  - `resolve` → `check_conflict` → `alert_only`；`check_conflict` 仅当 `conflict_feedback=True` 且 LLM 判定 `classification ∈ {TP,FP}` 与 `Alert.verdict.label`（官方真值）**冲突**时，写回 `fb-{dataset}-{alert_id}` feedback 片段（`method="conflict"`、`classification=真值`、`upsert_fragments` 幂等、审计 `conflict.feedback`）；未冲突或规则直发一律不写（选择性沉淀）。
- `make_triage_resolver(llm, cache=None)`：返回 `resolve(alert, hits, evidence=None)`，按 `fingerprint(alert)`（sha1 前 16 位）缓存；LLM 不可用/失败回退规则结论。
- seq 防泄漏：`graph.invoke(_default_state(seq, alert))` 中 `seq` 必须与记忆库该数据集片段序号对齐（从 1 起），证据与模式只引用 `seq < 当前` 的经验。

### 5.5 多层记忆

`src/core/memory/models.py`：`Fragment`（`fragment_id/dataset/alert_id/seq/host/ts_ms/rule_id/rule_level/groups/mitre/classification/verdict_priority/method/llm_error/summary/source/created_at`，`embed_text` 属性返回 `summary`）、`Pattern`（`kind ∈ behavior|burst|fp_noise`、`state ∈ draft|active|superseded`）、`DerivedRule`、`now_ms()`。

`src/core/memory/store.py`：`MemoryStore(db_path="data/memory/memory.db", chroma_dir="data/memory/chroma")`。

- SQLite（`PRAGMA journal_mode=WAL`，`check_same_thread=False` + `RLock`）建表与索引：
  - `fragment`（PK `fragment_id`；索引 `(dataset,rule_id)`、`(dataset,host,ts_ms)`、`(dataset,seq)`）
  - `pattern`（PK `pattern_id`；索引 `(dataset,state)`）
  - `rule`（PK `rule_id`；索引 `(rule_type,state)`；含 `auto/audit` 列）
  - `audit`（自增 id；索引 `(scope,obj_id)`）、`evo`（KV，PK `k`）
- 片段写入：`add_fragments(frags, embed=True)` 纯跳过重复（幂等 `frag-*`）；`upsert_fragments(frags, embed=True)` 整行覆盖更新（复核更正/feedback 场景，`fb-*`），二者向量侧均 `col.upsert`。
- 向量：`_collection_ref()` 惰性 `import chromadb` + `PersistentClient` + `get_or_create_collection("fragments", hnsw:space=cosine)`；未装/取模型失败则打印后置 `_collection_failed=True` 并**降级为 SQLite 近似**（`search_fragments` 回退为规则 id + 关键词计数排序）。`embed_all(dataset=None)` 用于降级后补齐；`_EMBED_BATCH=400` 分批。
- 查询：`fragments/fragment_by_ids/fragment_ids_all/fragment_seqs/count_fragments`；`search_fragments(query, k=10, dataset=None)` 语义召回后回 SQLite 取全量。
- 模式：`add_pattern/pattern_by_id/patterns(state,dataset)/pattern_patch/patterns_of_fragments`；`pattern_patch` 允许 `title/description/state/confidence/kind/derived_rule_id`，`by!="system"` 记 `edited_by` 与 `manual.edit` 审计。
- 规则：`add_rule/rule_by_id/rules(state)/rule_patch/rule_set_state/rule_delete/bump_fired/set_fired/pattern_merge_link`；`_patch_rule` 统一写路径（revision+1、audit JSON 回写、审计表行）。
- 升格/拒绝：`promote_rule(rule_id, by, note)`（`auto=0`、`owner=人工`、来源模式 meta 标记、审计 `manual.promote`、登记 evo `promoted.manual`，幂等）；`reject_candidate`（仅退出候选推荐，登记 evo `promote.rejected`，规则保持 active）；`promoted_rule_ids()/rejected_rule_ids()`。
- 总开关与 KV：`auto_evolve(on=None) -> bool`（evo 键 `auto_evolve`，默认 `"1"` 即开）；`evo_get(key, default)/evo_set(key, value)`。常用 evo 键：`miner.reject.{dataset}`、`promote.rejected`、`promote.explain.{rule_id}`、`promoted.manual`。
- 审计与快照：`audit(scope, obj_id, op, by, note)`、`audit_log(scope, obj_id, limit=50)`；`stats()` 返回片段/模式/衍生规则计数与开关状态。

`src/core/memory/evidence.py`：`EvidenceBuilder(store, kb=None)`。

- `similar_past_fragments(query, dataset, seq_now, k=8)`：`search_fragments` 取 30 条后只保留 `seq < seq_now`。
- `_past_patterns_all(dataset, seq_now)`：只保留"全部支撑片段都早于当前"的模式——支撑片段必须同数据集且 `seq < seq_now`，片段 id 前缀兼容 `frag-{ds}-` 与 `fb-{ds}-`。
- `past_patterns(dataset, seq_now, k=4)`；`active_patterns_covering_rule(dataset, rule_id, seq_now)`（v3 分流判定用）。
- `kb_lines(techniques)`：`kb.alert_graph` 结果转 `Technique → 战术 / 使用团伙数` 文本；图谱异常时返回空，不阻断研判。
- `collect(dataset, query, techniques, seq_now, with_memory=True, with_kb=True, k_frag=8, k_pat=4) -> {"evidence_text": str, "counts": {"frags","patterns","kb"}}`：组装 `[参考·多层记忆...]` 与 `[参考·ATT&CK 知识图谱]` 两段证据。

### 5.6 自进化（模式挖掘 → 衍生规则）

`src/core/evolve/common.py`：`level_sev(level)`（阈值 12/7/4/1 → Critical/High/Medium/Low）、提示词 `SYSTEM_INDUCE`（要求输出 `meaningful/title/description/mitre_techniques/mitre_tactics/severity/confidence`）、`now_ms` 复用。

`src/core/evolve/miner.py`（常量 `WINDOW_MS=180000`、`MIN_DISTINCT_RULES=3`、`MIN_EVENTS=4`、`MAX_SPAN_EVENTS=240`）：

- `chain_candidates(frags)`：同主机 3 分钟滑动窗内 ≥3 条不同规则且 ≥4 条事件 → 非重叠、按支撑数优先的 `behavior` 候选。
- `fp_noise_candidates(frags, min_size=3, fp_ratio=0.6)`：同 `rule_id` 片段中 FP 占比 ≥0.6 且样本 ≥3 → 降噪提议。
- `PatternMiner(store, llm=None, kb=None, max_llm=8, min_noise=3).mine(dataset) -> list[dict]`：
  - 已有非 superseded 模式指纹与 `evo.miner.reject.{dataset}` 拒绝指纹去重（防复活）；
  - 对 `behavior` 候选按支撑数优先走**有界 LLM**（`_induce` 有预算 `max_llm`，无论采纳与否都扣预算）；`meaningful=false` 记 `miner.skip` 审计并把指纹持久化到拒否键；LLM 不可用/失败则 `_fallback` 启发式归纳；
  - 模式 id `pat-{dataset}-{YYYYMMDD}-{NNNN}`，state=`active`，`kind=behavior`；若有 `kb` 则解析 MITRE 技术并补全 tactics；
  - `fp_noise` 直接按统计成模式（不调 LLM）。全部记 `miner.create` 审计。

`src/core/evolve/derive.py`：`RuleCompiler(store, by="system")`。

- `compile_one(p)`：跳过无规则 id 或 `hits<2` 的模式；若某 active 衍生规则的 rule.id 集合与之相同 → `pattern_merge_link` 合并（模式 `superseded` + 审计）不重复建；否则生成 `DR-{YYYYMMDD}-{NNNN}`，`severity` 取模式支撑片段的最大告警等级映射，`action_policy` 高危为 `{"max_tier":"A1","allow":["snapshot","query"]}` 否则 `{"max_tier":"A0","allow":[]}`；`kind=fp_noise` 强制 `state=draft`、`enabled=False`、`severity=Low`，`behavior` 为 `active`；回填 `pattern.derived_rule_id`（溯源）。
- `run(dataset)`：受 `store.auto_evolve()` 门控，关闭时只返回 `auto_evolve=False` 与保留模式清单；开启时遍历该数据集 `state=active` 且无 `derived_rule_id` 的模式编译。
- `replay_baseline(dataset)`：按该数据集片段回放，统计"本数据集模式编译出的"active 衍生规则命中成员规则的事件次数，`set_fired` 回写 `fired_times/last_triggered_at`。

### 5.7 知识图谱

`src/core/knowledge/graph.py`：`KnowledgeKB(db="data/kb/attack_kuzu")`。

- `_resolve_ascii_path`：非 ASCII 路径回退 `SCSSA_KUZU_DB` 或 `%TEMP%\scssa_kb\attack_kuzu`。
- 实体/关系（由导入脚本建）：节点 `Tactic/Technique/ThreatActor/Mitigation/Meta`；关系 `SUBTECHNIQUE_OF/HAS_TACTIC/USES/MITIGATES`。
- `_find_technique(code)`：`^T\d{3,5}(\.\d+)?$` 精确 ID 匹配，否则按名称 `CONTAINS` 模糊（LIMIT 3）。
- `resolve_mitre(techniques, tactics=None) -> {"techniques","tactics"}`；`alert_graph(techniques) -> {"techniques":[{attack_id,name,tactics,actors}]}`（告警→技术→战术/团伙数，最多 6 个技术）。
- `stats()` 返回 Meta 与 Tactic/Technique 计数；查询异常向上抛，由 `EvidenceBuilder`/调用方捕获降级。

`scripts/ingest_attack_kuzu.py`：`--source`（默认 `data/kb/enterprise-attack.json`）、`--db`（默认 `data/kb/attack_kuzu`）、`--rebuild`（删旧库重建）。源缺失时先直连 MITRE GitHub 再走镜像下载（`ghfast.top` 等）；跳过 revoked/deprecated 对象。实测导入 Tactic=15、Technique=697（活跃）、ThreatActor=1057、Mitigation=44，边 HAS_TACTIC=872 / SUBTECHNIQUE_OF=475 / USES=17136 / MITIGATES=1448。

## 7. 编码规范与协作约定

1. **命名**：模块/函数小写下划线；Pydantic 模型与类用 CamelCase；规则/模式/片段/衍生规则遵循 ID 约定——片段 `frag-{ds}-{seq:05d}`、feedback `fb-{dataset}-{alert_id}`、模式 `pat-{dataset}-{YYYYMMDD}-{NNNN}`、衍生规则 `DR-{YYYYMMDD}-{NNNN}`；审计 `scope ∈ {fragment,rule,pattern}`。
2. **类型注解**：公开函数必须带类型注解；数据契约统一用 Pydantic v2（`extra="ignore"` 容忍上游多余字段）。
3. **日志/输出**：按 `模块.功能` 前缀的中文短句 print（如 `[memory]`、`[evo]`、`[smoke]`）；不打印密钥；运行日志与跑批产物落 `log/`。
4. **存储访问收敛**：业务代码不直接拼 SQL，统一经 `MemoryStore`；图查询统一经 `KnowledgeKB`；LLM 调用统一经 `LLMClient`。
5. **错误归因优先**：每个研判/动作/衍生规则可回溯（命中规则 → 模式 → 片段，或规则 → 模式 → 片段）；排查先归因再改。
6. **变更同步文档**：改动架构/流程时同步更新《系统架构.md》《开发指南.md》；跑批实验结论写《实验记录.md》（含复现命令与产物路径）。
7. **安全与门控**：自动演化必须经总开关 `auto_evolve` 且有审计；`.env`/密钥不入库；高风险动作默认人工确认。

## 8. 常见问题与规避

（对齐《开发指南》§7）

1. **数据集读取**：linux-APT CSV 为多段表头拼接，勿直接 `pandas.read_csv`；llm-soc 的 `rule_priority` 只是 level 映射，勿当真实严重度。
2. **LangGraph 版本 API**：以 `scssa` 内实际版本为准，`StateGraph/add_node/add_conditional_edges/compile` 各版本写法有差异，先跑冒烟再扩展。
3. **LLM 输出稳定性**：枚举/结构必须本地二次校验，非法回退规则结论；`extract_json_object` 已对未转义反斜杠做兜底。
4. **成本失控**：LLM 只处理需语义的告警；研判按 `fingerprint` 缓存；`miner` 有 `max_llm` 预算。
5. **自动演化失控**：衍生规则 CRUD 必须总开关 + 单条可停 + 每次变更审计 + 门控回放，防规则自激。
6. **前端联调**：Vite 代理 `/api`、`/ws` 避免 CORS；WS 断线重连（指数退避）与心跳兜底；后端长任务异步，勿阻塞事件循环拖垮大屏推送。
7. **大屏演示**：Mock 数据结构与真实字段一致，避免联调返工；演示机先 `npm run build` 由 FastAPI 托管，减少现场对 Node 的依赖。
8. **记忆污染**：低风险片段随时写；可疑模式/衍生规则必须门控后入库。
9. **StateGraph 状态键丢失**：`AgentState` 未声明的键会被静默丢弃（本项目实际踩过 v3 的 `manual_hits/channel`），新增跨节点状态必须显式声明。
10. **密钥泄露**：`.env`、证书一律 `.gitignore`；提交前自查。

## 9. 已知缺口与后续开发建议

1. **运行期"每条处置即时写 Fragment"未接线**：当前处置事件先落 `log/*.jsonl`，再由 `scripts/build_memory_baseline.py` 成批沉淀；在线链路尚无"每次决策即时写片段"。建议在处置流 `feedback` 节点或 Ingress 后置钩子接 `MemoryStore.upsert_fragments`。
2. **挖掘器未做周期/事件触发**：`PatternMiner.mine` 目前仅由 `run_evolve_baseline.py` 手动触发；"feedback/相似样本达阈值自发再挖"未实现。建议复用 LangGraph 状态图或独立后台任务（与处置流解耦）。
3. **优先级定级口径未统一**：LLM 按内容定级与官方按规则等级定级不一致（实验显示优先级命中率提升组未超基线），后续需统一判据或仅以 TP/FP 为主指标。
4. **A3 审批与 NL 编译向导未接入后端**：前端 `actions/decide/hosts/nlCompile` 仍走 `mockDb.ts`；A0–A3 动作分级与 HITL 尚未在处置流落地（v1 边界=仅 notify）。
5. **图谱单指标净负**：消融显示图谱单独注入为净负（UNKNOWN 率升高），联合组增益基本来自记忆块，图谱检索策略（候选取数/融合权重）待优化。
6. **配置加载**：《开发指南》规划的 `pydantic-settings + .env` 与当前 `dataclass + os.getenv` 实现不一致；若需 `.env` 支持，建议统一到 `pydantic-settings` 并补齐端口类配置（当前端口硬编码默认值）。
7. **测试固化**：离线评测脚本（事件日志 vs 官方标注的 178 基准）尚未固化为一等公民；建议补充 pytest 化回归。
