## 2. 项目概述

### 2.1 赛题背景

- 赛事：2026 年度中国青年科技创新"揭榜挂帅"擂台赛，学生赛道。
- 赛题编号/方向：XH-202614「AI+安全大模型平台的智能体研究」。
- 作品名称：**自进化多维度服务器安全智能体**。
- 作品定位：以大语言模型为决策中枢，融合本地网安知识图谱（Kùzu，ATT&CK 起步）与分层记忆系统，构建"规则底座—模式认知—数据溯源"三级联动的安全决策体系，覆盖"自动化感知 → 智能研判 → 实时预警 → 闭环处置 → 经验迭代"。

### 2.2 目标

1. 打通一条可演示的最小闭环：告警归一化 → 双规则池命中 → 显意识（LLM）研判 → 分级动作/通知 → 经验沉淀。
2. 构建"**历史片段 → 可疑模式 → 衍生规则**"多层记忆与双类规则体系（人工规则仅人工增删改；衍生规则系统自动 CRUD + 门控 + 审计）。
3. 落地"自进化人机协同闭环"：处置分流 → 复核 feedback 回流 → 样本累积挖模式 → 前端呈现待升格候选 → 人工拍板升格为人工规则。
4. 提供监控大屏 + 后台管理的可视化前端，支撑评审演示。

### 2.3 范围界定

- 初赛阶段**只用本地两数据集模拟数据**（流式回放器经统一 Ingress 投递）完成训练、分层记忆构建与闭环验收。
- **真实 SIEM（Wazuh）在线接入不在初赛待办**：系统经统一 `Alert` 模型与数据源解耦，未来仅需新增数据源适配器。
- 两个数据集：`linux-APT-Dataset-2024`（Wazuh Linux 审计流，模拟数据主体）与 `LLM-SOC-Alert-Triage`（178 条带标签 Windows/Sysmon 告警基准，研判评测集）。

## 4. 技术方案总结

### 4.1 总体架构与三层联动

- 纵向分层：① 数据接入与归一化 → ② 规则层（双规则池）→ ③ 决策中枢（LangGraph + LLM）→ ④ 多层记忆与知识 → ⑤ 前端与对外服务 → ⑥ 预警与自主行动 → ⑦ 自进化与观测。
- 三层联动职责：

| 层 | 认知归属 | 载体 | 输出 |
|---|---|---|---|
| L1 规则命中 | 潜意识 | 规则引擎（人工规则 + 衍生规则双池） | 命中记录 + severity + 候选动作，累计生效次数 |
| L2 模式认知 | 潜意识 | 可疑模式匹配（片段向量召回 + 图模式命中） | 相似模式与片段上下文 |
| L3 决策中枢 | 显意识 | LangGraph 工作流 + LLM + 静态知识库 | 研判结论 + 动作执行 + 反馈 |

### 4.2 认知分层

- 潜意识（System 1 · 快）：人工规则 + 衍生规则 + 多层记忆模式匹配，确定性、高召回、低延迟、可解释。
- 显意识（System 2 · 慢）：LLM 语义研判、跨域推理与模式归纳，由潜意识未覆盖/低置信输入唤醒。
- 经验累积闭环：显意识决策/反馈沉淀为历史片段 → 挖掘为可疑模式 → 编译为衍生规则注入规则池；"潜意识越用越厚，显意识越用越省"。
- 数据集对应运行路径：`linux-APT` 演示纯潜意识快判（规则回退），`llm-soc` 演示显意识推理（DeepSeek 实判）。

### 4.3 双规则池

| 属性 | 人工规则 | 衍生规则 |
|---|---|---|
| 权限 | 仅人工增删改（支持自然语言辅助） | 系统自动动态增删改，可人工修改/停用/冻结 |
| 来源 | 人工 / NL 助手 | 由"可疑模式"自动编译生成 |
| 生命周期 | active/draft/paused/expired | draft → active → superseded/deleted（自动）+ 人工可 pause/freeze |
| 审计 | 记录操作人 | 每次自动增删改写审计，可一键暂停"自动演化" |

规则条件使用结构化 JSON DSL 谓词，作用于统一 `Alert` 字段；每条规则含 `severity` 与 `action_policy`，并统计 `fired_times`（生效次数）。

### 4.4 多层记忆与知识图谱

- 分层记忆：历史片段（SQLite 事件表 + Chroma 向量）→ 可疑模式（Kùzu/JSON + 向量）→ 规则（SQLite）。
- 存储决策：轻量起步（SQLite 结构化 + Chroma 语义检索 + Kùzu 嵌入式图库），接口层屏蔽实现便于切换。
- 知识图谱：Kùzu 收录 MITRE ATT&CK 企业版（STIX 2.1）；实测导入 Tactic=15、Technique=697（活跃）、ThreatActor=1057、Mitigation=44，边 HAS_TACTIC=872 / SUBTECHNIQUE_OF=475 / USES=17136 / MITIGATES=1448（见开发指南 §2.5）。
- 动态溯源：`Host/User/Process/File/Command/NetworkFlow/Alert/Pattern` 节点与 ATT&CK 本体桥接，支持"告警→技术→战术"多跳查询。

### 4.5 处置流版本演进

| 版本 | 关键行为 | 状态 |
|---|---|---|
| v1 | 规则命中 → LLM 研判 → 仅 `notify`（无自主动作） | 已跑批 |
| v2 | 增加可选 `gather_evidence` 节点，注入证据后 triage（默认关，等价 v1） | 已实现并接线（`--joint-evidence`） |
| v3 | 按**命中源裁决**三态分流：`manual` 人工规则直发不耗 LLM / `memory` 必走 LLM 注入证据 / `policy` 无记忆命中按成本策略 | 已落地并冒烟通过 |

- v3 事件带 `channel` 字段；可选 `--conflict-feedback` 仅在 LLM 判定与官方真值冲突时写回 feedback 片段（`method=conflict`、幂等、审计）——选择性沉淀。
- 防泄漏约束：模式/片段证据仅取当前告警之前（流式切分；模式须全部支撑片段均早于当前）。

### 4.6 人机协同升格闭环

状态机：`人工规则处置 → 复核/反馈(feedback fragment) → 记忆样本累积 ≥N → 新可疑模式（有界 LLM 归纳 + 审计） → 作为证据辅助下一轮 LLM 研判 → 验证有效 → 前端呈现待升格候选 → 用户拍板升格为人工规则 → 重新处置`。

权威分级：① 人工规则（仅人工增删改，命中直发）；② 可疑模式/衍生规则（自动 CRUD + 门控 + 审计 + 可冻结，只建议不裁决）；③ feedback/历史片段（低权威经验原料，随时写）。任意跳步可溯源：规则 → 模式 → 片段。

### 4.7 自主行动分级

| 级别 | 说明 | 默认确认 |
|---|---|---|
| A0 仅通知 | 记录 + 通知（默认） | 无 |
| A1 只读自主 | 取证快照、查询溯源、生成研判报告 | 无 |
| A2 受限自主 | 告警聚合/抑制、隔离可疑进程等 | 需规则显式允许 |
| A3 处置动作 | 封禁 IP、杀进程、隔离主机等 | 必须人工确认（HITL） |

## 5. 实验结果与结论

### 5.1 v1 首轮全量研判（llm-soc 178，已实测）

- 运行配置：2026-09-07，conda `scssa`；`deepseek-chat`，temperature=0；`--llm-policy all`（178 条全部语义研判）。
- 运行现象：规则命中 178/178（规则池 74 条种子）；LLM 需研判 178 → 实判 176，**2 次响应 JSON 非法自动回退规则结论**（`llm_error=true`）；动作集合仅 `['notify']`。

| 指标 | 值 |
|---|---|
| 混淆矩阵 | TP=70 / FP=8 / FN=34 / TN=66 |
| 准确率 Acc | 0.7640 |
| 检出精确率 Precision | 0.8974 |
| 检出召回率 Recall | 0.6731 |
| 检出 F1 | 0.7692 |
| 优先级一致率（LLM priority vs gt_priority） | 96/178 = 53.9% |

结论：精确率 89.7%、F1 76.9% 尚可，**召回偏低（67.3%）**——漏检 34 条官方 TP 集中于低危规则（level=3 漏 16、level=4 漏 6）。优先级一致率仅 53.9%，因 LLM 按内容定级与官方按 Wazuh `rule.level` 映射的定级口径不一致。

### 5.2 联合决策消融（llm-soc 178，流式防泄漏，已实测）

- 方法：基线复用历史**无上下文** LLM 处置事件（零新增调用）；增强组真实调用 DeepSeek 注入证据：`+记忆`（相似片段 + 可疑模式 + 命中衍生规则，仅取 seq<当前）、`+图谱`（ATT&CK Technique→Tactic/使用团伙）、`+联合`。

| 组 | acc_all | acc_decided | macro F1 | UNKNOWN | prio% | 翻转(改对/改错) |
|---|---|---|---|---|---|---|
| 基线（无上下文） | 0.758 | 0.780 | 0.780 | 1.69% | 53.9% | — |
| +图谱(kb) | 0.736 | 0.766 | 0.766 | 3.93% | 53.9% | 3/7（净 −4） |
| +多层记忆(mem) | **0.803** | **0.812** | **0.812** | 1.12% | 48.9% | 16/8（净 +8） |
| +联合(joint) | 0.803 | 0.812 | 0.812 | 1.12% | 50.0% | 17/10（净 +7） |

结论要点：
1. 多层记忆证据注入带来一致增益（约 **+4.5pp**，翻转改对/改错 16/8，TP 精确率 0.92），是主要增益来源。
2. 图谱**单独注入为净负**（UNKNOWN 率升高至 3.93%）；联合组有效增益基本来自记忆块，图谱未贡献额外净增益。
3. 优先级一致率增强组**均未超过基线**（48.9%/50.0% vs 53.9%），证据对"分级"帮助不足，是下一迭代重点。
4. 覆盖率非解释因素：记忆召回 ≥1 条片段 174/178（97.8%），图谱注入 147/178（82.6%）。
5. 局限：**单次运行、翻转样本量小**（净 ±≤17 条），结论方向需在阶段六闭环中复用评估。

### 5.3 v3 处置分流冒烟与 no-LLM sanity（已实测）

- 隔离冒烟 `scripts/smoke_triage_v3.py`：**16/16 通过**（临时副本记忆库）。验证：人工规则命中→`manual` 直发且 LLM 不得被唤醒；模式命中（防泄漏）→`memory` 必走 LLM 且衍生规则 `fired_times` +1；仅"处置与真值冲突"才写回 feedback（幂等 + 审计）。
- no-LLM sanity（真实库）：llm-soc 178 → `memory` 174 / `policy` 4 / `manual` 0；linux 前 200 → `policy` 200（防泄漏过滤后无相似记忆，故 0 次 LLM）。
- linux-APT 9,357 条离线跑批：`llm_used=0`（纯规则回退，演示潜意识快路径）。
- 环境限制：因真实库中人工规则 0 条、feedback 片段 0 条，`manual` 通道尚无真实数据触发（**未验证**于真实库，仅隔离冒烟覆盖）。

### 5.4 前端联通验证（已实测）

- 后端 127.0.0.1:8000：`/api/health` 返回 `ok=true`，`available=[llm-soc, linux]`，`dist=true`。
- `/api/dashboard`：todayTotal=178、Critical=11/High=60/Medium=10/Low=97、hosts=5、rulesActive=74。
- WS `/ws/feed`：收到 `hello → start → alert…` 帧序列，观众驱动从头回放验证通过。
- 静态 SPA：`/`、`/screen`、`/admin/alerts` 均返回 200。

### 5.5 与官方 ML 基线对照

数据源论文给出的传统 ML 基线（TF-IDF + 5 折 CV，`ml_baseline_results.csv`）：**Linear SVM Acc 88.2% / Precision 90.5% / Recall 89.4% / F1 89.6%**，明显高于本作品 v1 的 Acc 76.4% / F1 76.9%。该对照表明：传统"规则+ML"在二分类精度上仍是强基线，LLM 的价值主要在**解释/推理链与闭环可进化能力**，而非原始分类精度。差距是后续迭代需正视的量化目标。

| # | 缺口 | 影响 | 建议动作 | 优先级 |
|---|---|---|---|---|
| 1 | 运行期"每条处置即时写 Fragment"未接线，经验沉淀仍依赖离线批处理（`build_memory_baseline.py`） | 在线/演示时经验无法实时累积，自进化滞后于处置 | 在处置流 `feedback` 节点接入 `MemoryStore.upsert_fragments`，与 demo review 侧保持幂等 | 高 |

## 8. 经验与教训

1. **LangGraph 使用 TypedDict 状态时，未声明的键会被静默丢弃。** 曾导致 `channel`、`manual_hits` 等字段无法跨节点流通；解决方式是凡需跨节点传递的状态键必须在 `State` 中显式声明。
2. **Kùzu Windows 版不支持非 ASCII 路径**，而本项目路径含中文。规避：库文件实际落在 `%TEMP%\scssa_kb\attack_kuzu`，生产建议用环境变量 `SCSSA_KUZU_DB` 指向任意 ASCII 目录；导入脚本对非 ASCII `--db` 自动回退。
3. **LLM 输出必须本地二次校验。** 实际出现 2 次 JSON 非法（多余字符/未转义反斜杠，如 `C:\Windows`），需对 `extract_json_object` 增加容错，且解析失败时回退规则结论，保证事件仍有 `action=notify`。
4. **消融必须防泄漏。** 证据只能取当前告警之前（流式切分，模式须全部支撑片段早于当前），否则指标虚高、结论不可信。
5. **数据集读取不能想当然。** linux-APT CSV 多段表头拼接、列宽杂乱（约 113,173 行不可归因），必须做"表头对齐 + 语义校验 + 丢弃不可靠行"三步清洗，仅 9,357 行可靠；llm-soc 的 `rule_priority` 只是 `rule.level` 映射，不能当真实严重度。

## 10. 结论

本作品已完成阶段一至阶段六的主体交付：环境与工程骨架就绪，两数据集归一化为统一 `Alert`（linux-APT 可靠解析 9,357 条、llm-soc 178 条），Agent 核心（双规则池 + LangGraph 处置流 + LLMClient + Kùzu ATT&CK）与多层记忆自进化（片段 9,535 → 可疑模式 36 → 衍生规则 36）完成离线跑批，Vue3 大屏 + FastAPI 前后端与观众驱动回放实现演示联通，处置分流 v3、复核 feedback 写回、证据面板与升格审批构成的"人机协同闭环"已落地并通过隔离冒烟。已实测指标方面，v1 首轮全量 Acc 0.7640 / F1 0.7692，联合决策消融显示多层记忆注入带来约 +4.5pp 增益（0.758 → 0.803），但优先级一致率（53.9%）与官方 ML 基线（Linear SVM Acc 88.2% / F1 89.6%）仍有明显差距；同时存在"运行期即时片段沉淀未接线、挖掘器未事件触发、优先级口径不统一、pytest 未落地、全量回放压测未做"等已识别缺口。总体而言，项目在"可演进的闭环能力"上已跑通端到端演示链路，但在**分类精度、分级一致性与工程化测试/压测**三方面仍需重点补齐，不宜夸大现阶段的指标表现。
