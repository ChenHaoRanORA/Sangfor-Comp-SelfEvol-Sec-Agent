## 2. 测试目标与策略

### 2.1 测试分层

| 层次 | 目标 | 载体 / 主要产物 |
|---|---|---|
| 单元/模块冒烟 | 单点能力正确（LLM 客户端、规则引擎、JSON 容错、记忆库幂等） | `src/core/**`、`scripts/*` 内联断言 |
| 冒烟（隔离） | 在**临时副本记忆库**上验证闭环，避免污染真实库 | `scripts/smoke_close_loop.py`、`scripts/smoke_triage_v3.py` |
| 集成/离线跑批 | 全量告警走通"规则命中 → LLM 研判 → 落库" | `scripts/run_agent_v1.py`、`log/agent_v1_*.jsonl` |
| 评测/消融 | 用官方标签量化模块价值（开/关对照） | `scripts/eval_joint_decision.py`、`log/eval_joint/*` |
| 前端验收 | REST/WS 契约、SPA 路由、构建与类型检查 | `src/core/api/server.py`、`web/dist`、`npm run build` |

### 2.2 错误归因与消融验证原则

1. **错误归因优先**：每条结论必须可回溯（命中规则、来源模式、支撑片段、图谱技术）——证据链 = 规则 → 模式 → 片段。
2. **消融验证**：模块价值用"开/关对比"验证（无上下文基线 vs +记忆 vs +图谱 vs +联合），不凭直觉。
3. **防泄漏**：流式切分，证据只含**当前告警 seq 之前**的片段/模式（模式须全部支撑片段早于当前），防止未来信息泄漏。
4. **只写实测**：区分"已实现且实测""已实现未实测""未实现"，未实测不写为通过。

### 2.3 通过判定标准

| 层次 | 通过判据 |
|---|---|
| 单元/模块 | 断言全部成立；异常路径按设计回退（如非法 JSON → 规则回退） |
| 冒烟（隔离） | 脚本退出码 0；`smoke_close_loop.py` 输出 `ALL 15 CHECKS PASSED`；`smoke_triage_v3.py` 输出 `PASS=16 FAIL=0` |
| 集成/离线跑批 | 告警总数与输入一致；动作集合符合版本边界（v1 仅 `['notify']`）；落库计数正确 |
| 评测/消融 | 增强组相对基线指标可解释（升/降方向明确），防泄漏校验通过 |
| 前端验收 | REST/WS 返回结构与契约一致；SPA 路由 200；`npm run build`（含 vue-tsc 类型检查）成功 |

> 注：`smoke_close_loop.py` 任一断言失败即 `sys.exit(1)`；`smoke_triage_v3.py` 汇总后以 `SystemExit(1 if FAIL else 0)` 退出。

### 3.3 评测集口径

- 评测以 llm-soc 178 条为基准，"威胁检出"为正例，官方 TP/FP 为真值。
- 优先级：`gt_priority` 来自官方 `rule_priority`；预测优先级为 LLM 输出（规范化到 low/medium/high/critical）。
- 联合决策消融基线复用历史**无上下文** LLM 处置事件（`log/agent_v1_llm_soc_full_178.jsonl`，零新增调用），增强组真实调用 DeepSeek。

### 3.4 评测输入与产物约定

| 项 | 约定 |
|---|---|
| 告警输入 | `data/processed/llm_soc_alerts.jsonl`（178 条，seq 按行序从 1 起） |
| 基线条目 | `log/agent_v1_llm_soc_full_178.jsonl`（逐条复用其 `verdict.classification/priority`） |
| 逐条结果 | `log/eval_joint/{arm}.jsonl`，字段含 `seq/alert_id/gt/gt_priority/cls/priority/method/evidence/calls/cost_s` |
| 汇总结果 | `log/eval_joint/summary.json`，按 arm 输出 `n/acc_all/acc_decided/macro_f1_decided/tp/fp/unknown_rate/none_rate/priority_exact` |
| 续跑 | 存在 `{arm}.jsonl` 时按 `seq` 跳过已完成条目（可断点续跑）；`--fresh` 删除重跑 |
| 断言 | 脚本内断言 `len(alerts) == len(events) == 178`，否则中止 |

### 5.3 结论解读

1. **多层记忆证据有效**：mem 组相对基线分类 acc/macro-F1 一致提升约 **+4.5pp**（TP 精确率 0.92），是当前唯一带来净增益的模块。
2. **图谱单独注入为净负**：kb 组 acc 下降、UNKNOWN 率升至 3.93%；joint 组的增益基本被记忆块覆盖，图谱未贡献额外净增益。
3. **优先级分级是短板**：增强组优先级命中率均未超过基线（48.9%~53.9%），证据对"定级"帮助不足。
4. **覆盖率非解释因素**：记忆召回≥1 片段 174/178（97.8%）、图谱注入 147/178（82.6%）。
5. **口径提示**：本轮为**单次运行、样本量小（178 条，翻转净变化 ≤17 条）**，结论为方向性，需在阶段六闭环中复评；优先级命中率受"LLM 按内容定级 vs 官方按规则等级定级"口径差异影响，见 §6 缺陷 D-01。

### 5.4 指标定义与防泄漏实现

| 指标 | 定义（`scripts/eval_joint_decision.py`） |
|---|---|
| acc_all | 全部 178 条中预测分类（含 UNKNOWN/None）与真值一致的比例 |
| acc_decided | 仅在预测为 TP/FP 的"决定子集"上的准确率 |
| macro_f1_decided | TP/FP 两类 F1 的算术平均（在决定子集上计算） |
| unknown_rate | 预测为 UNKNOWN 的比例 |
| none_rate | 预测为 None（未给出分类）的比例 |
| priority_exact | 预测优先级与真值优先级（规范化后）精确相等的比例 |

防泄漏实现要点：
1. `EvidenceBuilder.collect(..., seq_now=seq)` 只检索 `seq < 当前` 的片段；
2. 模式命中要求其**全部支撑片段的 seq 均早于当前**（`smoke_triage_v3.py::first_cover` 与评测脚本同口径）；
3. 消融增强组复用历史基线事件的 `fingerprint` 做记忆化（`memo`），避免同一告警重复调用；相同指纹命中时不重算。

## 6. 缺陷与改进跟踪

| 编号 | 现象 | 影响 | 归因 | 处理状态 |
|---|---|---|---|---|
| D-01 | 优先级一致率仅 49%~54% | 分级指标不可直接对比 | LLM 按内容定级，官方 `rule_priority` 由规则 level 映射，两者判据不一致 | 未解决（评测口径需统一判据或只看 TP/FP）；已列入遗留 |
| D-02 | 2 次 LLM 响应 JSON 非法 | 该 2 条回退规则结论，削弱语义研判 | 模型输出含多余字符/非法转义（如未转义反斜杠） | 部分缓解：提示词约束 + `extract_json_object` 增强反斜杠容错（TC-008） |
| D-03 | 图谱单独注入净负（kb acc 0.736 < 基线 0.758） | 直接注入图谱证据反而降低分类质量 | 图谱上下文（Technique→Tactic/团伙）与当前判别任务弱相关，引入噪声并抬高 UNKNOWN | 已定位：联合组不再单独依赖图谱，增益主要来自记忆块 |
| D-04 | LangGraph 未声明的状态键被静默丢弃 | v3 的 `manual_hits`/`channel` 等无法在节点间流通 | LangGraph 按 `TypedDict` 建通道，未声明键不传递 | 已修复：在 `AgentState` 中显式声明全部跨节点键（含注释说明） |
| D-05 | Kùzu（Windows）不支持中文等非 ASCII 路径 | 本项目路径含中文，图库文件无法落在默认路径 | Kùzu Windows 窄字符路径限制 | 已缓解：库文件落 `%TEMP%\scssa_kb\attack_kuzu`；支持环境变量 `SCSSA_KUZU_DB` 指向 ASCII 目录；非 ASCII `--db` 自动回退（TC-023） |
| D-06 | 漏检 34 条官方 TP 集中于低危规则 | 召回偏低（0.673） | LLM 倾向将低危 Sysmon 行为判 FP（level=3 漏 16、level=4 漏 6） | 观察中：候选方案为提示词引导"低危但上下文成链"+ 记忆证据补充（mem 组召回提升已验证方向） |

## 8. 遗留风险与未测项

1. **优先级/定级口径未统一**：一致率 49%~54%，评测判据需统一（见 D-01）。
2. **运行期"每条处置即时写 Fragment"未接线**：目前仅 review 侧 feedback 与 v3 冲突沉淀写回；每条处置事件实时沉淀仍走 build 脚本成批处理（未测/待补）。
3. **挖掘器未做周期/事件触发**：模式挖掘仍为脚本触发，闭环"样本累积→自动再挖"未实现（未测/待补）。
4. **无自动化单元测试框架**：pytest 未落地，现有冒烟为独立脚本（未测/待补）。
5. **linux-APT 全量回放稳定性未压测**：崩溃率/P95 时延/LLM 成本无完整数据（未测/待补）。
6. **真实 SIEM 在线接入不在范围**：Wazuh/靶场在线接入列为未来扩展，未测。
7. **A3 高危动作执行与 HITL 审批流**：未端到端实测（未测/待补）。
8. **NL 规则创建向导**：未端到端验收（未测/待补）。
9. **消融为单次运行、样本量小**：翻转净变化 ≤17 条，结论为方向性，需复评。
