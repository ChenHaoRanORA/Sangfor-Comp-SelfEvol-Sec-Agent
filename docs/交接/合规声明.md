## 2. 声明范围与合规基线

### 2.1 本项目合规基线

本项目为**非商业性质的学生竞赛作品**，遵循以下基线：

1. **尊重上游许可**：所有引用的第三方代码、数据集、知识库均按其原始许可使用，不删除原始版权与许可声明。
2. **最小必要使用**：仅使用为完成"告警研判 + 自进化闭环"研究所需的字段与数据，不做超出原始用途的二次分发。
3. **不外泄密钥与私有数据**：密钥、环境变量、大数据集与第三方资源均**不入版本库**（`.gitignore` 排除，见 §5.1）。
4. **人工权威优先**：涉及真实处置动作（A2/A3 级）必须有规则显式允许或人工确认，LLM 仅作建议（见 §6.3）。
5. **可追溯**：自进化链路（片段 → 模式 → 衍生规则）与规则变更全程留痕、可审计、可一键冻结（见 §7）。

### 2.2 不合规风险声明

本作品当前为**离线/本地实验室环境**研究原型，**未接入任何生产 SIEM 或真实业务系统**，亦未对真实生产环境执行任何处置动作。任何在真实环境中的部署，均需由部署方自行完成如下评估：数据出境合规、等保/关基合规、LLM 服务商数据处理协议、内部安全审查与变更审批。

### 5.2 数据集中的个人信息与敏感信息

- 两份数据集均为**公开发布的研究数据集**（由 Wazuh/Sysmon 在**隔离实验网**内采集），包含主机名、内网 IP、用户名等字段（如 `192.168.204.x`、`sohaib`）。
- 本项目处理原则：
  1. **不回查、不关联**真实自然人；不对其中的账号/主机做任何识别、画像或关联分析。
  2. 演示与截图**仅在本地实验室环境**进行；如对外展示，建议对 username/主机名/内网 IP 做脱敏或使用合成样本（**待办，见 §8**）。
  3. 不将数据集内容与任何外部数据源做碰撞比对。

### 5.3 数据出境与第三方处理（LLM 调用）

> **这是本项目最需要关注的合规点。**

- 系统的"显意识"研判会将**告警文本**（含 `full_log`/命令行/文件路径等）发送至 **DeepSeek 官方 API**（`https://api.deepseek.com`，模型 `deepseek-chat`）进行处理。
- 合规含义：
  1. 使用公开研究数据集时，属于**公开数据**，出境/第三方处理风险可控；
  2. 一旦接入**真实生产告警**，告警内容可能含敏感主机名、账号、路径、命令等，构成对外数据传输，**必须先完成**：内部数据出境评估、与模型服务商的数据处理协议（不用于训练等）、必要的字段脱敏或本地化模型替代。
- 本项目现状：**未接入生产数据**；LLM 调用仅面向公开数据集，并已在实现文档中披露该数据流。

### 5.4 存储安全

- 本地存储：SQLite（`data/memory/memory.db`，WAL 模式）+ Chroma 向量目录 + Kùzu 图库，均为**本地文件**，无云端回传、无第三方遥测。
- 前端服务**默认绑定 `127.0.0.1:8000`**（[server.py](file:///e:/Comp/Projects/Sangfor-Comp-SelfEvol-Sec-Agent/src/core/api/server.py#L305-L306)），同源托管构建产物，**未开启任何公网暴露**。注意：CORS 当前为 `allow_origins=["*"]`（[server.py](file:///e:/Comp/Projects/Sangfor-Comp-SelfEvol-Sec-Agent/src/core/api/server.py#L65)），且**无身份认证与权限控制**；若需对外演示，必须先收紧 CORS、增加鉴权与网络隔离（见 §8 第 1 项）。

## 6. AI 生成内容与自主行为合规

### 6.1 AI 生成内容声明

- 系统的"研判结论（`Verdict`）"、"规则自然语言解释（规则建议页）"、"模式归纳文本"均由大语言模型生成，**属于 AI 生成内容（AIGC）**。
- 约束措施：
  1. LLM 输出**必须经本地 JSON 结构化校验**，非法输出（如未转义反斜杠）自动回退规则结论，防止"未校验的 AI 文本"直接进入处置链（[client.py](file:///e:/Comp/Projects/Sangfor-Comp-SelfEvol-Sec-Agent/src/core/llm/client.py) `extract_json_object`）。
  2. LLM 输出仅作为**决策建议**，不作为唯一定级依据；定级口径与官方口径的差异已在文档中披露（一致率约 49~54%，未夸大）。
  3. 前端对 AI 生成的解释内容**显式标注来源**（`source=llm` / `source=template` 降级），用户可见其生成方式。

### 6.2 自主行为分级与人类在环（HITL）

| 级别 | 行为 | 合规控制 |
|---|---|---|
| A0 | 仅通知 | 无风险 |
| A1 | 只读自主（取证快照、溯源查询） | 无副作用 |
| A2 | 受限自主（聚合/抑制等） | **须规则显式允许** |
| A3 | 处置动作（封禁/杀进程/隔离） | **必须人工确认**（`/admin/approvals` 审批队列） |

> 声明：本项目**从未、也不会在未经人工确认的情况下对真实系统执行 A3 级动作**；当前实现中动作集合默认仅 `notify`。

### 6.3 自进化的权威边界

- **人工规则**：仅人工增删改，命中后**直发**，不消耗 LLM（人工权威，永不被系统自动修改）。
- **可疑模式 / 衍生规则**：系统可自动 CRUD，但**只建议、不裁决**；带门控（`auto_evolve`）、审计、可冻结/停用。
- **升格**：由新模式升格为人工规则**必须由用户在"规则建议"页拍板**（同意/拒绝），系统不得自行升格。

## 7. 审计与可追溯性承诺

| 承诺 | 实现载体 |
|---|---|
| 规则变更可追溯 | 衍生规则每次自动增删改均写审计（`audit` 表）；触发者、时间、变更前后可查 |
| 自进化链路可溯源 | 规则 → 模式 → 支撑片段三层可回跳（`derived_rule_id` / `source_pattern`），支持 Kùzu 多跳与记忆库查询 |
| 处置与真值冲突可追溯 | 仅在"LLM 判定与官方标签冲突"时选择性沉淀 `feedback` 片段（`method=conflict`），幂等 upsert + 审计（`conflict.feedback`） |
| 升格/拒绝可追溯 | 用户"同意升格/拒绝"均写审计（`manual.reject` 等）与 `evo` 记录（`promote.rejected`），拒绝后不再推荐 |
| 防泄漏可验证 | 证据仅取当前告警之前（seq < 当前；模式须全部支撑片段早于当前），保证评测结论不被未来信息污染 |
| 实验可复现 | 原始评测产物（`log/eval_joint/*.jsonl`、`summary.json`）保留，指标一律以源文件为准 |
