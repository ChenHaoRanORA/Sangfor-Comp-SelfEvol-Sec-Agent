# 开发计划

> 顶层计划总览。详细架构见 [系统架构.md](./系统架构.md)，分阶段落地任务与完成定义（DoD）见 [开发指南.md](./开发指南.md)，数据集说明见 [../data](../data)。

### 项目概念
一个基于知识图谱与分层记忆系统的**自进化网络安全智能体**，以大语言模型为核心算力与决策中枢，融合本地网安专业知识图谱（Kùzu，ATT&CK 起步）、动态攻防模式经验与全维度审计数据，构建“**规则底座-模式认知-数据溯源**”三级联动的安全决策体系。

- **双类规则**：人工规则仅人工增删改（支持自然语言辅助编写）；衍生规则由系统自动动态增删改、可人工修改；每条规则统计**生效次数**。
- **分层记忆**：“历史片段 → 可疑模式 → 规则”，衍生规则可逐层溯源到模式与片段证据。
- **分级自主行动**：A0 通知 / A1 只读 / A2 受限 / A3 处置（必须人工确认 HITL）。
- **数据入口统一**：所有告警经**一个网络通讯接口（Ingress）**接收；**初赛阶段只用本地两数据集模拟数据**（回放器投递）完成训练、分层记忆构建与闭环验收；真实 Wazuh 在线接入已从待办删除（列为未来扩展）。
- 实现：规则引擎与大模型（LangGraph 工作流）双驱动，覆盖 自动化感知 → 智能研判 → 实时预警 → 闭环处置 → 经验迭代，解决传统设备规则固化、泛化弱、误报漏报高、无自进化能力等痛点，面向大规模服务器集群场景。

### 自进化人机协同闭环（规格 v1）
> 权威说明：系统"经验 → 研判 → 规则升格"的人机协同闭环。自进化产物先以**低权威形态**存在，**升格必须人工拍板**，全程审计。关联：系统架构 §2.3/§2.4、开发指南 §4.3/§6.1。

**A. 处置分流（规则匹配 = 双向匹配）**
1. 入流告警先做**双向匹配**：人工规则库（确定性权威）+ 多层记忆库可疑模式（相似片段/共现链/历史误报簇）。
2. 命中**人工规则** → 一般无需 LLM，直接按规则定级告警（`need_llm=False`）；照常记命中计数与经验片段。
3. 命中**可疑模式**（或未命中人工规则但有相似记忆）→ 视为需要**显意识研判**：LLM 结合"图谱多跳 + 多层记忆相似样本"推理（`gather_evidence` → 注入 triage）。模式命中只表示"与历史样本相似"，不替代语义判定。
4. LLM 结论/衍生规则提示为**建议**；人工规则结论为**权威**（可覆盖，留审计）。

**B. 事后反馈回流（纠错入记忆）**
5. 人工复核/事后验证发现**人工规则处置不合适** → 把"告警+原处置+复核结论+理由"以 `feedback` 片段写入多层记忆（低权威、随时写），不直接改规则。
6. 复核结论与处置归属（哪条规则/哪个模式/LLM）一并记录，供归因。

**C. 样本累积 → 可疑模式（自进化中间态）**
7. feedback/相似样本在记忆中**达到一定量**（同类误判累积 / 语义簇成形）→ 周期性挖掘抽象**新可疑模式**（含"曾误判/重演"标签）；沿用有界 LLM 归纳 + 审计 + 拒否指纹防复活。
8. 新模式进入记忆库，作为下一轮研判的**辅助证据**（作用于 A3），不直接当规则用。

**D. 升格（人机协同 · 人工权威）**
9. 新模式**事后被证明有意义**（命中新样本 + 验证有效/持续 TP）→ 系统在规则管理页呈现**待升格候选**（带溯源：模式→支撑片段→验证统计），由**用户决定是否升格为人工规则**。
10. 升格 = 创建人工规则（此后命中直发、不耗 LLM）；不升格可保留为模式或停用；操作均写审计。

**E. 权威边界（状态机收口）**
- 人工规则：仅人工增删改；命中直发、不耗 LLM；可标记复杂场景需 LLM。
- 可疑模式 / 衍生规则：系统自动演化，门控 + 审计 + 可冻结，**只建议不裁决**。
- 闭环：`人工规则处置 → 复核/反馈(fragment) → 样本累积 ≥N → 新可疑模式 → 辅助 LLM 研判 → 验证有意义 → 用户升格人工规则 → 再处置`；任意跳步均留证据链：规则→模式→片段。

| # | 阶段 | 阶段要点 | 目标（详见开发指南） |
|---|---|---|---|
| 一 | 搭建环境 | conda `scssa`（langgraph/openai/fastapi/kuzu/chromadb…）；`.env` 配置；Node/Vue3 前端 | 环境可跑通 + 大屏 Mock 首页 |
| 二 | 数据接入与数据集构建（离线） | **统一 Ingress**（HTTP Webhook，预留 Syslog/WS）；清洗归一化 linux-APT / llm-soc → 统一 `Alert`；回放器经 Ingress 投递 | 回放 1000 条零崩溃 |
| 三 | Agent 核心能力开发 | 双规则池规则引擎（生效计数）；LangGraph 处置流；LLMClient（研判/模式归纳/规则编译/NL 规则助手）；Kùzu 图谱导入 ATT&CK | llm-soc 178 条跑通研判闭环 |
| 四 | 多层记忆与自进化（离线训练） | 历史片段（SQLite+Chroma）→ 可疑模式（LLM+图谱）→ 衍生规则自动 CRUD；溯源入 Kùzu；**以两数据集离线跑批产出初始衍生规则分层记忆基线** | 衍生规则可分层检索/溯源 |
| 五 | 前端与闭环测试 | Vue3 监控大屏 + 后台（监测状态 / 告警历史 / 规则管理含生效次数与 NL 创建 / A3 审批）；A0–A3 动作；离线评测（178 基准）与消融 | 完整离线 Demo 可演示 |
| 六 | 自进化人机协同闭环验收（模拟数据） | 处置分流（双向匹配）+ 证据注入 → 复核 feedback 回流 → 样本累积挖模式 → 升格审批；**处置分流 v3 已落地（2026-09-08）：命中源裁决三态（人工规则直发 / 可疑模式→必走 LLM / 策略回退）+ 仅『效果冲突』选择性沉淀，隔离冒烟 16/16** | 模拟数据下走通一次完整闭环，逐步可溯源/回滚（真实 Wazuh 接入不在初赛待办） |

### 技术选型
| 层 | 选型 |
|---|---|
| 数据载体 | 本地两数据集（模拟数据）+ 流式回放器；真实 SIEM/Wazuh 不在初赛范围 |
| LLM 编排 | LangGraph（工作流/Agent，checkpoint + HITL）；openai 客户端（结构化输出，OpenAI 兼容端点） |
| 后端/接口 | FastAPI（REST + WebSocket + Ingress Webhook） |
| 前端 | Vue3 + Element Plus + ECharts（监控大屏 + 后台，演示）；Streamlit（仅内部调试） |
| 存储 | SQLite（规则/片段/动作/审计）+ Chroma（向量）+ Kùzu（专业知识图谱与溯源，networkx 导出/原型） |
| 知识库 | 本地网安专业知识图谱：ATT&CK 企业版（STIX）起步，后续扩展 CVE/CAPEC/CWE/KEV |

### 数据与运行模式
- **统一网络通讯接口 Ingress**：`POST /api/v1/ingest`（Webhook 为主，预留 Syslog/TCP、WebSocket），幂等去重与限速。
- **模拟数据回放（初赛默认）**：回放器把本地两数据集按时间压缩投递 Ingress，用于功能联调、分层记忆/规则构建与闭环验收、评测消融（真实 SIEM 在线接入不在初赛待办）。
  - [linux-apt-dataset-2024](https://www.kaggle.com/datasets/yacinenaoui/linux-apt-dataset-2024) —— Wazuh/APT Linux 审计流（模拟数据主体）
  - [LLM-SOC-Alert-Triage](https://github.com/c0deing/llm-soc-alert-triage) —— 多源攻击告警带标签基准（研判评测）
