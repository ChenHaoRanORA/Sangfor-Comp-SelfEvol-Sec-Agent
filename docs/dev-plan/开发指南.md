# 开发指南

> 配套文档：《开发计划.md》《系统架构.md》与 `docs/data/` 两份数据集说明
> 目标：指导在 conda 环境 **`scssa`** 中，用 **LangGraph（工作流/Agent 编排）+ openai（LLM API 通讯）+ FastAPI + Vue3（Element Plus/ECharts）演示前端**落地"双类规则 + 历史片段—可疑模式—规则多层记忆 + 分级自主行动"的自进化服务器安全智能体（Streamlit 仅作内部调试工具）。

---

## 1. 总体开发原则

1. **纵向打通优先**：先做出"告警 → 规则命中 → LLM 研判 → 通知/动作 → 历史片段"的最小闭环，再扩展模式挖掘、衍生规则、前端面板。
2. **错误归因优先**：每个研判/动作/衍生规则都能追溯（命中规则、来源模式、历史片段、记忆/知识引用）；排查问题先归因再改。
3. **消融验证**：模块价值用"开/关对比"验证（加模式记忆前后、衍生规则开/关），不凭直觉上线。
4. **规则分治**：人工规则只能人工增删改；衍生规则由系统自动 CRUD、可人工修改；自动演化必须有总开关与审计。
5. **进化有门控、行动有分级**：可疑模式→衍生规则必须回放验证；动作按 A0–A3 分级，高危 A3 强制人工确认。
6. **成本可控**：只有需语义判断的告警才走 LLM；先规则后模型。

### 2.5 网安知识图谱建库（Kùzu + ATT&CK 起步）
- 定位：本地"静态网安知识库"= **专业知识图谱**，用 **Kùzu** 嵌入式图库（`pip install kuzu`，无需 Docker/服务，Cypher 类查询，Python 内嵌）。溯源子图与后续 CVE 等扩展共用同一 Kùzu 库；networkx 仅作导出/原型。
- 数据获取（官方/开放许可，阶段一首选 ATT&CK）：
  | 源 | 地址 | 说明 |
  |---|---|---|
  | ATT&CK 企业版（STIX 2.1） | `https://raw.githubusercontent.com/mitre/cti/master/enterprise-attack/enterprise-attack.json` | MB 级，CC BY 4.0；首阶段导入它即可 |
  | CISA KEV（后续） | `https://www.cisa.gov/known-exploited-vulnerabilities-catalog` | 已被利用漏洞 CSV |
  | NVD CVE（后续） | `https://nvd.nist.gov/vuln/data-feeds` | GB 级，按需筛子集 |
  | CAPEC/CWE（后续） | capec.mitre.org / cwe.mitre.org 官方导出 | 攻击模式/弱点 |
- 导入步骤：解析 STIX 对象——`x-mitre-tactic`→Tactic、`attack-pattern`→Technique、`relationship`→边（`subtechnique_of/uses/mitigates`…）；以 ATT&CK ID（如 T1078）为主键建 `Tactic/Technique` 节点表与关系表；Technique 的 description/别名文本可同步进 Chroma 做向量召回。
- 动态桥接：告警/片段的 `rule.mitre.*` → 查 Tactic/Technique；模式挖掘节点把归纳的可疑模式挂到对应 Technique，形成"告警→技术→战术/同族告警"多跳查询。
- 演示用法：前端大屏/后台可展示"命中技术图谱子图"；LLM 研判上下文 = Chroma 向量候选 + Kùzu Cypher 多跳结果。
- 落地状态：`scripts/ingest_attack_kuzu.py`（STIX→Kùzu，缺源自动下载、`--rebuild` 重建、内置演示查询）已跑通；实测导入 Tactic=15、Technique=697(活跃)、ThreatActor=1057、Mitigation=44，边 HAS_TACTIC=872 / SUBTECHNIQUE_OF=475 / USES=17136 / MITIGATES=1448，查询验证通过。
- Windows 注意：Kùzu(Windows) 窄字符路径不支持中文等非 ASCII，而本项目路径含中文，故库文件实际落在 `%TEMP%\scssa_kb\attack_kuzu`。生产建议设环境变量 `SCSSA_KUZU_DB` 指向任意 ASCII 目录（如 `D:\Data\scssa\kb\attack_kuzu`）；脚本对非 ASCII `--db` 会自动回退该变量或 Temp。

### 2.6 数据入口与运行模式（统一网络通讯接口 Ingress）
- **单一数据入口**：所有告警/事件经**一个网络通讯接口**接收（先实现 HTTP Webhook `POST /api/v1/ingest`，预留 Syslog/TCP、WebSocket），数据来源与业务解耦。
- 运行模式：
  - **模拟数据回放（初赛默认）**：回放器按时间压缩把本地两数据集投递到 Ingress；目标 = 功能联调 + 基于数据集**构建"衍生规则分层记忆系统"**（历史片段→可疑模式→衍生规则）与人机协同闭环验收、评测消融（llm-soc 178）。
  - **真实接入（未来扩展 · 不在初赛待办）**：Wazuh/靶场告警转发到同一 Ingress（仅需新增数据源适配器），初赛不涉及。
- 约定：Ingress 收到的是"原始告警文本/JSON"，统一交给归一化器转 `Alert`；Ingress 需支持幂等（去重）与限速，便于回放与压测。

## 3. LLM 访问层（openai 客户端）

`src/core/llm/client.py`：

```python
from openai import OpenAI
from src.config import settings

class LLMClient:
    def __init__(self):
        self._client = OpenAI(
            api_key=settings.llm_api_key, base_url=settings.llm_base_url,
            timeout=settings.llm_timeout, max_retries=settings.llm_max_retries)

    def chat_json(self, system: str, user: str, schema: dict | None = None) -> dict:
        kwargs = {}
        if schema is not None:
            kwargs["response_format"] = {"type": "json_object"}
        resp = self._client.chat.completions.create(
            model=settings.llm_model,
            messages=[{"role": "system", "content": system},
                      {"role": "user", "content": user}],
            temperature=0.0, **kwargs)
        return resp.choices[0].message.content  # 调用方 json.loads + 校验
```

规范：
- 不同任务（研判 / 模式归纳 / 规则编译 / NL 规则生成）各建提示词模板，输出统一走 JSON + 本地枚举/结构二次校验，非法回退规则结论。
- 研判输出口径（对齐 llm-soc）：`classification ∈ {TP,FP}`、`priority ∈ {Low,Medium,High,Critical}`、`justification`、`evidence_ids`、`suggested_actions`。
- 所有 LLM 调用记录结构化日志（模型/耗时/token/输入指纹），供成本与消融分析。

## 4. LangGraph 工作流开发指南

### 4.1 处置流（LangGraph，离线/在线共用）
```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, END

class State(TypedDict, total=False):
    alert: dict          # 统一 Alert
    rule_hits: list      # 命中规则（含生效次数自增）
    evidence: list       # 模式/片段/溯源/知识库上下文
    verdict: dict        # LLM 研判结果
    action_plan: list    # 分级动作
    action_results: list
    need_confirm: bool

def rule_match(s: State): ...      # 双规则池匹配，更新 fired_times
def gather_evidence(s: State): ... # 查可疑模式/片段/溯源/静态KB
def llm_triage(s: State): ...      # 调 LLMClient
def decide_action(s: State): ...   # 依据 rule.action_policy 生成 A0-A3 动作
def execute_action(s: State): ...  # A0-A2 直执行，A3 置 need_confirm
def feedback(s: State): ...        # 写入历史片段、误报修正

g = StateGraph(State)
g.add_node("rule_match", rule_match); g.add_node("gather_evidence", gather_evidence)
g.add_node("llm_triage", llm_triage); g.add_node("decide_action", decide_action)
g.add_node("execute_action", execute_action); g.add_node("feedback", feedback)
g.set_entry_point("rule_match")
g.add_edge("rule_match", "gather_evidence"); g.add_edge("gather_evidence", "llm_triage")
g.add_edge("llm_triage", "decide_action"); g.add_edge("decide_action", "execute_action")
g.add_edge("execute_action", "feedback"); g.add_edge("feedback", END)
# HITL：对 A3 用 interrupt()/checkpointer 挂起待人工确认后恢复
```
要点：
- 关键分支（"是否需 LLM""是否 A3 动作"）用 `add_conditional_edges`。
- 用 **checkpointer**（先 `langgraph.checkpoint.memory`，再迁 SQLite）持久化图状态，支持断点恢复与人工确认。
- HITL：A3 动作在 `execute_action` 前 `interrupt`（或独立确认节点）挂起，前端"人工确认"接口恢复执行。
- 自进化流（模式挖掘→衍生规则 CRUD）作为另一张周期图或后台任务，与处置流解耦。

### 4.2 与 LangChain 的关系
- 用 LangGraph 承担**有状态、需人机交互的流程**（处置/进化/规则确认）。
- 单次工具式调用（如检索）直接调函数，不强制包 Agent。

### 4.3 经验累积流水线（现状 · 认知映射见《系统架构.md》§2.3）

当前"多层记忆累积经验"是一条**离线批处理流水线**，链路为：

| 环节 | 载体/实现 | 产物 | 状态 |
|---|---|---|---|
| ① 经验产生 | `scripts/run_agent_v1.py`：每条告警走 LangGraph 处置流 → 处置事件 JSONL（命中规则 + verdict/justification/method/llm_error） | `log/agent_v1_*.jsonl` | ✅ 已实现（离线） |
| ② 底层 · 片段沉淀 | `scripts/build_memory_baseline.py` → `MemoryStore.add_fragments`（SQLite 结构化 + Chroma 向量，幂等 `frag-{ds}-{seq}`） | fragment 表（当前 9535）+ 向量 | ✅ 已实现 |
| ③ 中间层 · 模式归纳 | `PatternMiner.mine(ds)`：片段簇启发式（行为链共现 / 高 FP 噪声）+ **有界 LLM** 归纳为可疑模式；拒否指纹持久化 `evo.miner.reject.{ds}` 防复活 | pattern 表（36） | ✅ 已实现 |
| ④ 顶层 · 规则固化 | `RuleCompiler.run(ds)`：active 模式 → 衍生规则自动 CRUD（受 `auto_evolve` 门控、全审计）→ 回填 `pattern.derived_rule_id`；`replay_baseline` 回放 fired 基线 | rule 表（36：active 27 + draft 9） | ✅ 已实现 |

要点：
- **一条告警的处置 = 一次经验沉淀**：事件逐条转 `Fragment`（摘要=规则描述+判定理由，保留 method/classification/host/time/原始 source），供向量检索与模式归纳。
- **显意识 → 潜意识固化**：LLM 研判（显意识）沉淀为片段 → 挖掘成可疑模式 → 编译为衍生规则注入潜意识规则池；人工冻结/停用/改字段同样写库 + 审计。重跑全链路幂等。
- **当前边界（缺口）**：运行期实时回流此前只有 build 脚本调用 `add_fragments`——页面复核不回写记忆、Agent 决策即时写未接。**2026-09-08 最小在线闭环 v2 已关闭其中两处（演示层）**：
  1. demo 人工复核 `/alerts/{id}/review`（含理由/优先级）→ **feedback 片段**即时写回记忆（`fb-{dataset}-{alert_id}`，`upsert_fragments` 覆盖幂等，source 记原处置归属 + 复核人/理由，审计 `manual.review`）；
  2. 复核→feedback 积累可作为新模式归纳的样本（挖掘链路仍为脚本触发）；
  3. **处置流内部自动 feedback 节点已关闭**：v3 `check_conflict` 节点——仅当 LLM 判定(TP/FP)与官方真值冲突才写回 `fb-*`（`method=conflict`、幂等、审计 `conflict.feedback`），入口 `run_agent_v1 --triage v3 --conflict-feedback`，冒烟 16/16；仍缺口：demo/在线每次决策即时写片段、挖掘器"处置后自发再挖"（事件/周期触发）。
- **补齐点（对应阶段六"模拟数据人机协同闭环"）**：① 处置流 `feedback` 节点与 demo review 接口接入 `MemoryStore.upsert_fragments`（片段即时沉淀）——review 侧已在"最小在线闭环 v2"闭环（2026-09-08），处置流自动节点已由 v3 `check_conflict`（仅冲突写回）关闭；运行期"每条处置事件即时写 Fragment"仍走 ① 之后 build 脚本成批沉淀，未实时接线；② 在线 review/feedback 写回记忆驱动误报修正——已闭环（feedback 片段 + 证据面板 + 升格候选，见阶段六清单）；③ 挖掘器改周期/事件触发（复用 §4.1 状态图或后台任务，与处置流解耦）——未实现。

## 6. 评测与消融方法论

- **离线基准**：llm-soc 178 条，分类 `accuracy/精确率/召回/F1/FPR`；优先级按 `macro`；对照官方 ML 基线（Linear SVM Acc≈88%）与论文 8 模型。
- **回放回归**：linux-APT 流回放，观测崩溃率、P95 时延、LLM 成本、命中/误报变化。
- **消融维度表**（每个改动开/关对照）：

| 变量 | 开 | 关（基线） |
|---|---|---|
| LLM 研判 | 规则命中后走 LLM | 仅按规则 level 直接判级 |
| 模式上下文 | 注入可疑模式/相似片段 | 不注入 |
| 静态知识库 | 注入 ATT&CK/CVE 检索结果 | 不注入 |
| 衍生规则自动演化 | 允许自动 CRUD | 冻结衍生规则库 |
| 历史片段记忆 | 命中历史影响研判 | 无记忆 |
| A0–A3 自主动作 | 按策略自动执行 | 仅通知 |

### 6.1 联合决策消融实测（2026-09-07 · llm-soc 178 · 流式防泄漏）

- **方法**：对 178 条带官方标签告警做"开/关"消融。基线 = 复用历史**无上下文** LLM 处置事件（与现提示词一致，零新增调用）；增强组 = 真实调用 DeepSeek 注入证据后研判：`+记忆`（相似历史片段 + 其可疑模式 + 命中衍生规则提示，仅取 seq<当前）、`+图谱`（ATT&CK Technique→Tactic/使用团伙）、`+联合`。防泄漏 = 流式切分（证据只含该告警之前的片段/模式，模式须全部支撑片段均早于当前）。
- **结果**（分类 Acc / 决定子集 Acc / 宏 F1 / UNKNOWN 率 / 优先级命中 / 相对基线分类翻转净好）：

| 组 | acc_all | acc_decided | macro F1 | UNKNOWN | prio% | 翻转(改对/改错) |
|---|---|---|---|---|---|---|
| 基线（无上下文） | 0.758 | 0.780 | 0.780 | 1.69% | 53.9% | — |
| +图谱(kb) | 0.736 | 0.766 | 0.766 | 3.93% | 53.9% | 3/7（净 −4） |
| +多层记忆(mem) | **0.803** | **0.812** | **0.812** | 1.12% | 48.9% | 16/8（净 +8） |
| +联合(joint) | 0.803 | 0.812 | 0.812 | 1.12% | 50.0% | 17/10（净 +7） |

- **结论**：① 多层记忆证据注入在分类准确率/宏 F1 上带来一致增益（约 +4.5pts，TP 精确率 0.92）；② 图谱**单独注入为净负**（UNKNOWN 率升高），联合组的有效增益基本来自记忆块（图谱未贡献额外净增益，其部分纠错行已被记忆覆盖）；③ 优先级命中率增强组均未超过基线 → 证据对"分级"帮助不足，是下一迭代重点。覆盖率非解释因素：记忆召回≥1 条片段 174/178（97.8%），图谱注入 147/178（82.6%）。
- **证据**：`log/eval_joint/{mem,kb,joint}.jsonl`（逐条，可续跑）与 `summary.json`；驱动 `scripts/eval_joint_decision.py`；证据组装 `src/core/memory/evidence.py`；注入点 `LLMClient.triage(..., evidence=...)`。**处置流 v2 已接线**：`make_v2_graph` 增加可选 `gather_evidence` 节点，`run_agent_v1 --joint-evidence` 启用（默认关等价 v1）。
- **附注**：单次运行、翻转样本量小（净 ±≤17 条），结论方向需在阶段六模拟数据闭环中复用评估；本轮顺带修复 `extract_json_object` 对模型输出中 `C:\Windows` 类未转义反斜杠的健壮性。

## 7. 常见坑与规避

1. **数据集读取**：linux-APT CSV 多段表头拼接，勿直接 `pandas.read_csv`（见数据说明 §4）；llm-soc 的 rule_priority 只是 level 映射，勿当真实严重度。
2. **LangGraph 版本 API**：以 `scssa` 实际版本为准；`StateGraph/checkpointer/interrupt` 写法不同版本有差异，先写冒烟。
3. **LLM 输出稳定性**：枚举/结构必须本地二次校验；`json.loads` 失败回退规则结论。
4. **成本失控**：LLM 只处理需语义的告警；研判加缓存（alert 指纹）与限额。
5. **自动演化失控**：衍生规则 CRUD 必须：总开关 + 单条可停 + 每次变更审计 + 门控回放；防止规则循环自激。
6. **前端联调**：Vite 开发代理配好 `/api`、`/ws`（避免 CORS）；WebSocket 断线重连与心跳要有兜底；后端长任务异步执行（asyncio/任务队列），勿阻塞事件循环拖垮大屏推送。
7. **大屏演示**：Mock 数据要与真实字段结构一致，避免联调阶段大面积返工；演示机上先 `npm run build` 由 FastAPI 托管，减少现场依赖 Node。
8. **记忆污染**：低风险历史片段可随时写；可疑模式/衍生规则必须门控后入库。
9. **密钥泄露**：`.env`、证书一律 `.gitignore`；提交前自查。
